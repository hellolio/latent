# 压缩摘要请求：做实增量 + 挂 SUMMARIZATION_SYSTEM_PROMPT

## 目标形态

- **首次压缩**：system = `SUMMARIZATION_SYSTEM_PROMPT` + user = `serialize_conversation(切点前全部范围)` + `SUMMARIZATION_PROMPT`（现状范围不变）。
- **再次压缩**：system = `SUMMARIZATION_SYSTEM_PROMPT` + user = `<previous-summary>最新摘要</previous-summary>` + `serialize_conversation(上次压缩 entry 之后 → 本次新切点之前的新消息)` + `update_summarization_prompt()`。
- 无 system 消息、无工具定义的现状保持；序列化对话**保留** `[Mode constraint]` 行（用户已确认）；摘要请求是一次性异构请求、不命中缓存，挂 system 提示词零额外代价。

## 改动 1：增量范围做实（crates/rpi-session/src/compaction.rs `run_compaction`，约 669-760 行）

`find_cut_point` 与 `first_kept` 不动，改"待摘要范围"的确定：

1. 在 `entries[..first_kept]` 内用 `rposition` 找最新一条 `Entry::Compaction`（记 `prev_idx`），取其 `summary` 作 `previous_summary`。
2. **无旧压缩** → 现状不变：全范围序列化 + `SUMMARIZATION_PROMPT`，空范围守卫（返回 `None`）保留。
3. **有旧压缩** → 只序列化 `entries[prev_idx+1..first_kept]`：
   - 新消息非空：conversation = `<previous-summary>` 标签 + `serialize_conversation(新消息)`，instruction 用 `update_summarization_prompt()`（其 "NEW conversation messages" 措辞从此名副其实）。
   - 新消息为空（新切点紧贴旧 compaction，之后无产生上下文消息的 entry）：返回 `Ok(None)`——旧摘要 + 保留尾部已覆盖全部信息；当前实现此时会全量重摘要，属浪费且语义错误。

旧摘要不再以 CompactionSummary → `[User]:` 行混入对话文本（消除重复）；模型的历史唯一来源是 `<previous-summary>`。

## 改动 2：文件清单跨次合并（compaction.rs）

`compute_file_lists` 改后只作用于新消息，会丢上次记录的文件。新增对偶解析：

- `parse_file_lists(summary: &str) -> (Vec<String>, Vec<String>)`：从旧摘要文本解析 `<read-files>`/`<modified-files>` XML 节（与 `format_file_operations` 对偶；缺节/解析失败返回空表，安全降级）。
- 增量路径：`compute_file_lists(新消息)` ∪ `parse_file_lists(旧摘要)`，BTreeSet 并集去重，read 集合剔除 modified 集合（沿用现有过滤语义）。
- `outcome.summary` 的 XML 附加节与 `details`（readFiles/modifiedFiles）写并集，供下次增量继续解析（跨次累积）。全量路径不变。

## 改动 3：摘要请求挂 system 提示词（crates/rpi-cli/src/assembly.rs `ProviderSummarizer`，约 1462-1516 行）

当前直接构造 `TranscriptContext { messages }`，改为走标准折叠入口：

```rust
let transcript = rpi_ai::normalize_context(rpi_ai::Context {
    system_prompt: Some(rpi_session::SUMMARIZATION_SYSTEM_PROMPT.to_string()),
    messages: llm_messages,
    tools: Vec::new(),
});
```

`SUMMARIZATION_SYSTEM_PROMPT` 已从 rpi-session/lib.rs:21 导出，assembly 直接引用；`run_compaction` 签名与 Summarizer trait 不变。

## 改动 4：无需改动的部分

切点算法（`find_valid_cut_points` 本就排除 Compaction entry）；两个提示词模板与 `UPDATE_SUMMARIZATION_INSTRUCTIONS` 文本；`tokens_before`（按完整投影估算）；assembly 的 SessionCompactor 流程；正常对话路径（系统提示词/工具/摘要消息组装完全不变）。

## 测试（crates/rpi-session/tests/session_tree_and_compaction.rs，复用 CapturingSummarizer）

1. **增量只发新消息**：旧消息 → `append_compaction` → 新消息，断言请求 conversation 含 `<previous-summary>` 与新消息、**不含**旧消息内容（"old question"/"old answer"），instruction 以 "The messages above are NEW conversation messages" 开头（强化现有 update-template 测试）。
2. **文件清单并集**：旧摘要带 `<read-files>`/`<modified-files>` 节，新消息再 read/edit 其他文件，断言 `details` 与 `outcome.summary` 的 XML 节为并集、read 已剔除 modified。
3. **无新内容返回 None**：compaction 后仅追加零上下文 entry，断言不发摘要请求、返回 `None`。
4. **system 提示词**（assembly 层或 rpi-session 层）：摘要请求经 `normalize_context` 折叠后首条消息为 system 且含 "context summarization assistant"。
