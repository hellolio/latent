# @ 文件选择器（交互 TUI，行为对齐上游 pi）

## 行为规格

**上游 pi 的语义（已核实并采纳）**：`@` 只是输入辅助——弹窗选文件/目录、选中往输入框插入路径文本；提交时 `@path` 作为普通文本发给模型，**不内联文件内容**，模型自行调 read 工具按需读取（read 自带 2000 行/50KiB 截断与续读）。用户手输 `@path`（不经弹窗）行为完全一致，无需提交端任何处理。

**弹窗**
- 触发：光标前最后一个空白分隔 token 以 `@` 开头时（任意位置，不限行首）；缓冲以 `/` 或 `!` 开头时让位（斜杠命令/bang 透传各有语义），不触发。
- 列表：cwd 下文件+目录（目录渲染带 `/` 尾缀）。用 `ignore` crate 进程内遍历（尊重 .gitignore；不用 pi 依赖的外部 fd 工具），叠加 `SearchIgnore`（内置默认表/项目 searchIgnore 配置）剪枝，排除 `.git`，含隐藏文件（对齐 pi `--hidden --exclude .git`）；按深度→目录优先→字母排序，采集上限 2000 条；弹窗展示 8 行可滚动（复用 `MAX_VISIBLE_ROWS`）。
- 过滤（对采集到的扁平递归列表内存过滤）：query 含 `/` 时按目录前缀下钻（`src/` → src 直接子项；`src/fo` → src/ 下 fo*）；否则对文件名打分（前缀 > 子串 > 模糊子序列，另含路径子串），目录优先，同分按路径排序。
- 键位（非模态，其余键照常进编辑器）：↑/↓ 选择、Tab/Enter 补全、Esc 关闭（query 变化后重开）。
- 补全：选中文件 → 光标处 token 替换为 `@相对路径 `（尾随空格，弹窗关闭）；选中目录 → `@相对路径/`（无空格，弹窗继续显示该目录子项，可下钻）；路径含空白时插入 `@"路径"` 引号形式（token 检测兼容 `@"` 前缀，保证含空格目录可继续下钻）。

## 改动清单（按依赖方向自底向上）

1. **latent-tools**：新增 `file_listing.rs`：`pub fn collect_entries(root, ignore: &SearchIgnore, max_entries) -> Vec<ListingEntry>`（`ListingEntry { path: String 相对路径, is_dir: bool }`；ignore crate 遍历设置参照 grep.rs 现有惯例 + SearchIgnore 剪枝 + 排序截断），lib.rs 导出；tempdir 单测。
2. **latent-tui**：
   - `editor.rs` 新增 pub API：`token_before_cursor() -> Option<(usize, String)>`（光标所在行、光标前的非空白 token，复用 `prev_word_index` 词边界；兼容 `@"` 引号前缀）与 `replace_token_before_cursor(replacement)`（push_undo → drain token → 私有 `insert_text` 插入，光标落插入尾部）+ 多字节/行中/undo 单测。
   - 新增 `file_popup.rs`（以 `command_popup.rs` 为模板）：`FileEntry { path, is_dir }`、`set_entries/clear_entries`、`sync(token)`（query=去 `@`/`@"` 前缀；dismissed 随 query 变化重置）、`filtered`（上述打分）、`complete_text() -> Option<(String, bool)>`（bool=是否保持弹窗：目录 true 文件 false）、`render`（同款圆角框，左列 `@path`）+ 组件单测；lib.rs 导出。
3. **latent-cli**（interactive）：
   - `state.rs`：`mention_popup: FilePopup` + entries 缓存字段 + `sync_mention_popup()`（token 检测 → 首次激活经 `collect_entries` 采集并缓存、失活清缓存；`/`、`!` 开头让位）。
   - `handlers.rs`：handle_key 顶部与 `sync_slash_popup` 并列同步；弹窗可见时的按键拦截块（↑↓ 移动；Tab/Enter 经 `editor.replace_token_before_cursor` 应用 `complete_text`，文件补全后 `dismiss()`、目录补全后 resync 保持）。
   - `view.rs`/`mod.rs`：弹窗渲染槽与 `popup_cap` 复用（与斜杠弹窗互斥取一，紧贴编辑器上方）。
   - `InteractiveCtx`/assembly：传入 cwd 与共享 `Arc<SearchIgnore>`（装配点已持有）。
   - `interactive/tests.rs`：状态级测试（@ 触发、过滤、Tab 补全替换 token、目录下钻保持、Esc）。
4. **E2E**：`scenarios/` 加响应脚本 + 新建 `test_file_mention.py`（测试 cwd 预置 README.md、src/main.rs 夹具）：① 输入 `@` → 断言弹窗出现 → 过滤 → Enter 选中 → 编辑器显示 `@README.md ` → 继续输入提问并提交 → `wait_for_requests` 断言请求 user 消息含 `@README.md` 文本且**不含**文件正文；② 目录下钻：`@`+选目录 → 弹窗显示子项。更新 tests/e2e/readme.md 场景清单。
5. **文档**：README.md 特性表加 @ 文件提及；AGENTS.md 目录索引补 `file_popup.rs`、`file_listing.rs` 行，e2e 场景数 26→27。

## 边界（明确不做）

- 不内联文件内容、不新增消息类型/发送 API/截断逻辑——模型经 read 工具读文件（既有能力）。print/json/rpc 模式不涉及。无新外部依赖（`ignore` 已在 workspace，latent-tools 已用）。

## 验证

`cargo build --workspace` + `cargo test --workspace` + `cargo clippy --workspace --all-targets` 全绿零警告；`cargo build --bin latent && cd tests/e2e && pytest test_file_mention.py -v` + 既有场景回归。
