# .latentignore：AI 忽略配置文件

## 目标与已确认决策

用 `.latentignore`（格式同 .gitignore）统一管理"AI 忽略哪些文件"，取代现有两条机制（settings.json `searchIgnore` + 代码内置 27 条默认表）：

1. **位置**：项目 `<cwd>/.latentignore` + 全局 `~/.latent/.latentignore`（全局只读不创建）。
2. **合并**：git 风格拼接——规则顺序 = 全局在前、项目在后，gitignore 语义 last-match-wins，项目可用 `!` 反选全局规则。
3. **内置默认表（DEFAULT_PATTERNS 27 条）整体删除**：无任何 `.latentignore` 时不做额外过滤（`.git` 的硬编码排除保留）。
4. **settings.json `searchIgnore` 字段移除**（本项目与全局均未配置过，无兼容包袱）。

匹配引擎换用 `ignore` crate 的 `GitignoreBuilder`（latent-tools 已依赖 ignore 0.4.33，`GitignoreBuilder` 非 feature 门控，**零新增依赖**），获得真正的 gitignore 语义：`!` 反选、`#` 注释、`dir/` 仅目录、`**`、`/` 锚定。现有 27 条内置模式全是裸名，与 gitignore 语义兼容，但本次直接删除不再迁移。

## 实施步骤

### 1. `crates/latent-tools/src/search_ignore.rs` — 重写为 gitignore 引擎

- 删除 `DEFAULT_PATTERNS` 与 `SearchIgnore::builtin()`。
- `SearchIgnore` 内部改为 `root: PathBuf`（= 会话 cwd，锚定用）+ `ignore::gitignore::Gitignore` + 正向模式列表；仍是廉价 Clone 共享。
- API 调整（调用方全在本仓，直接改签名）：
  - `from_patterns(root, lines) -> Result<Self, String>`：逐行 `GitignoreBuilder::add_line`，编译失败返回 Err；
  - `matches(relative, is_dir)`：增加 `is_dir` 参数（`dir/` 仅目录模式需要；`matched(...) == Match::Ignore` 即忽略）；
  - `is_empty()`：无任何规则行 = 关闭过滤；`patterns()`：仅返回非 `!` 正向行（供提示词回显）。
- 模块文档写明：拼接顺序、last-match-wins、被忽略目录剪枝后子项不可复活（git 同款限制）、不支持子目录级 `.latentignore`。
- 单测重写：反选/注释/仅目录/`**`/锚定/空文件关闭过滤/last-match-wins 顺序，替代原 globset 语义测试。

### 2. 四个消费点适配 + ls 补 `.git` 排除

- `file_listing.rs`、`grep.rs`、`find.rs`：`filter_entry` 处传入 `is_dir`（file_type 可得）。
- `ls.rs`：同上；并补上写死的 `.git` 排除（grep/find/@弹窗都有、唯独 ls 漏了，顺手对齐）。
- 三个工具 description 中硬编码的"node_modules, dist, target… excluded regardless"文案改为如实描述 `.latentignore` 机制（grep/find/ls 的 description 同步改）；检查是否有 description 契约测试需要更新。
- 全仓 `grep -rn "search_ignore\|searchIgnore\|SearchIgnore"` 清理全部引用。

### 3. `crates/latent-cli/src/assembly.rs` — 装配层

- `SettingsFile` 删除 `search_ignore` 字段。
- `load_search_ignore` 重写：按 `~/.latent/.latentignore` → `<cwd>/.latentignore` 顺序读文件（不存在静默跳过），逐行喂 builder，**坏行 eprintln 诊断 + 跳过该行**（手工编辑的文件容错优先），root = cwd。
- `SessionSettings.search_ignore` 字段保留（解析后的值对象），`Default` 改为空（不过滤）；`BuildOptions` 链路不变，`build_session` 仍不读文件。
- `search_ignore_rule`（系统提示词规则注入）保留，基于正向 patterns 生成；无规则时不出现在提示词。
- 重写现有 3 个 searchIgnore 测试为：文件发现（项目/全局/两者合并）、项目 `!` 反选覆盖全局、坏行跳过不影响其余规则、提示词规则回显。

### 4. latent-cli 其余引用更新

- `main.rs` 调用链不变；`interactive/mod.rs` 的 `mention_ignore` 加载自动受益。
- `src/modes/interactive/tests.rs`（`typing_at_opens_file_popup_filtered_by_search_ignore` 等）与 `tests/modes.rs` 中相关用例改为写 `.latentignore` fixture 驱动。
- grep 工具"无 .gitignore 也排除 dist"测试（grep.rs 内）改为 `.latentignore` fixture 驱动或删除。

### 5. E2E 新场景（按测试方针：新用户可见行为补场景）

新增 `tests/e2e/test_latentignore.py`：隔离 HOME 下写 `~/.latent/.latentignore`（全局）与项目 `.latentignore`，走 `@` 文件弹窗断言被忽略文件不出现在候选、`!` 反选可恢复；scenarios README 如有配置清单同步。

### 6. 文档

- `README.md`：勾掉 L209 todo，配置节补充 `.latentignore` 说明。

## 验收门槛

- `cargo build --workspace`、`cargo test --workspace`、`cargo clippy --workspace --all-targets` 全绿零警告；
- `cargo build --bin latent && cd tests/e2e && pytest -v` 新场景通过、file_mention 等相邻场景无回归。

## 明确不做

- 不支持子目录级 `.latentignore`（仅项目根 + 全局两处）；
- 不做热重载（与其他配置一致，启动时读一次）；
- `.git` 保持工具层硬编码排除，不进 `.latentignore` 体系（git 本身也永不追踪 `.git`）。
