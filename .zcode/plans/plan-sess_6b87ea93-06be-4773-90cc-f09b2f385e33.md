# 全屏模式:流式输出随滚动移动

## 根因

fullscreen 渲染(app.rs `render_fullscreen`)把屏幕分为 committed 历史窗口 + 钉底 tail;滚动偏移 `scroll_offset` 只作用于 committed(`viewport()`/`scroll_lines`,app.rs:518/704)。流式内容只存在于 `state.stream_text`/`pending_thinking`/`pending_tool_output`(tail 实时预览,`flush_stream` 在回合边界才转 committed),预览区自身只有「尾窗截断」(view.rs:263 恒显示最新 preview_cap 行),不是视口——故上滚时正在输出的部分结构性无法跟随滚动,且流式中较早的输出根本看不到。

## 方案

滚动锚扩展为「committed + 流式预览全量折行行」的组合内容坐标:

- **follow(贴底)模式:布局完全不变**(历史窗口 + 预览尾窗 + 钉底 chrome),现有行为与测试零变化(滚动数学在无预览时严格退化为现状)。
- **非 follow(滚动)模式**:视口 = committed + 预览全量行,占 `屏高 − chrome 高`;chrome(状态行、两行间隔、补全弹窗、编辑器、footer)仍钉底;预览尾窗不再单独渲染(其全量内容已在视口内,不再重复)。
- 滚动数学:`max_top = committed + 预览全量行数 − 视口高`;绝对锚定语义不变(上滚冻结,新内容在视口下方堆积);触底恢复 follow。过渡无缝:首次上滚时视口底边仍锚在最新输出行,继续上滚依次暴露流式中较早的内容,再往上才是历史 committed。
- 状态行(spinner)随编辑器一起钉底(输出内容滚动,输入区 chrome 不动)——与主流 TUI 一致。
- 已接受的取舍:flush(流式文本转 markdown 入 committed)与预览源切换(thinking→正文)瞬间,绝对锚定下视口内容一次性重排——与今天 follow 模式 flush 时的重排同级别,不做锚点补偿。

## 改动清单

**1. `crates/latent-cli/src/modes/interactive/state.rs`**
- 新增 `StreamWrapCache`:流式文本增量折行缓存。文本 append-only 时只重折最后一个未完成源行(`wrap_to_width` 按行独立,可精确增量);宽度/样式变化或文本收缩(flush/新回合)时全量重建;空文本 = 空。消除「每个 delta 帧对全量文本 O(n) 重算」(保持 view.rs:251 既有优化意图),并让「预览全量行数」可廉价获得。`InteractiveState` 挂 `stream_wrap` 字段。

**2. `crates/latent-cli/src/modes/interactive/view.rs`**
- `ViewportFrame` 增加:`preview_window: usize`(`lines` 头部属于预览尾窗的行数)+ `scroll_extra: Vec<UiLine>`(预览全量行,按内容顺序、已折行/截断、已着色)。
- 预览三分支(正文流式 / thinking / 工具卡片+实时输出)改为先产全量行(`scroll_extra`),尾窗 = 全量行尾切 `preview_cap`。正文分支改读缓存(替代 tail_chars 有界重算);thinking/工具输出的全量行设上限防极端开销(如工具输出尾 1000 行)。
- 选择列表 / 「添加模型」表单激活时:`preview_window = 0`、`scroll_extra` 为空(模态 UI 保持钉底)。

**3. `crates/latent-cli/src/modes/interactive/mod.rs`**
- `build_frame`:先 `state.stream_wrap.update(宽度, 样式)` 再调 `viewport`;`render_tick` 在 `app.render` 前调用 `app.set_scroll_tail(frame.preview_window, &frame.scroll_extra)`。

**4. `crates/latent-tui/src/app.rs`**(render 签名不变,现有 ~50 处测试调用零改动)
- 新字段:`scroll_window`/`scroll_extra`(setter 每帧注入)+ 缓存 `last_extra_len`/`last_chrome_len`/`last_preview_win`(render_fullscreen 折行后写;滚动 API 与 `frame_point` 读——与现有 `last_tail_len` 同一帧间模式)。
- `set_scroll_tail(window, full)` 注入滚动上下文(regular 模式忽略)。
- `render_fullscreen` 按 follow 分叉布局(共用整屏差分/选区高亮/光标钉底路径):follow 同现状;非 follow 时 vh = rows − chrome 高,top 对组合内容 clamp 并写回(`组合长 − vh` 可为负 → 内容贴底),视口行按 `top+sr` 取 committed 或 scroll_extra,chrome 从 tail 的预览窗口折行数之后起铺。
- `viewport()` 重构为 `fs_layout()`,`render_fullscreen` 与 `frame_point` 共用;非 follow 帧的 `last_tail_cells` 存 `scroll_extra ++ chrome`,保持「fr ≥ committed_len 索引 last_tail_cells」的复制不变量。
- `scroll_lines`/`scroll_page_*`/`scroll_top`/`scroll_bottom` 的 `max_top` 改组合坐标;`scroll_offset` 字段注释更新;模块头注释与 `fullscreen_pins_tail_to_bottom` 等既有语义描述同步。

**5. 测试**
- app.rs 单测(现有 4 个 fullscreen 滚动测试因 extra 为空行为不变):流式中上滚 → 更早预览行进视口、chrome 钉底、尾窗不重复;上滚冻结(extra 增长不移动视口);End/PageDown 恢复 follow;含 extra 的滚动数学(上滚 n 再下滚 n 回 follow);非 follow 帧跨 extra 行的选区高亮/复制。
- view.rs:长文本下 `preview_window = cap` 而 `scroll_extra` = 全量;select/form 激活时两者为空。
- state.rs:增量折行与一次性折行等价;宽度变化/文本收缩重建。
- E2E(新增用户可见行为,按测试方针补场景):`scenarios/fullscreen_stream_scroll.json`(长文本 turn + `delay_ms` 维持流式中,mock_llm.py:30/117 已支持 chunk 拆分与延迟)+ `test_fullscreen_stream_scroll.py`:流式进行中 PageUp → 早期输出可见、最新输出不可见、输入框钉底;End → 最新输出回到视口。现有 `test_fullscreen.py` 场景滚动发生在回复完成后,不受影响。
