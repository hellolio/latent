# 用 ratatui 重写 latent 的 interactive TUI(pi 风格)

## 现状与问题
- `crates/latent-tui`(1636 行)是零依赖手写 ANSI 差分渲染;`crates/latent-cli/src/modes/interactive.rs`(2144 行)是巨文件。
- 界面短板:启动只有两行文字、无分隔线/已加载资源列表;无 spinner;`Markdown` 组件闲置(assistant 正文按纯文本落盘);无代码高亮;单行输入;footer 无 cwd/git 分支;颜色为硬编码 3-bit SGR 常量、无语义主题;GREEN/BLUE/MAGENTA 定义了但未使用。

## 目标(pi 风格,ratatui + crossterm + syntect)
1. **启动区**:`latent v0.1.0`(accent 色 bold + dim 版本号)→ 快捷键提示行(键名 dim、描述 muted,`ctrl+o` 展开/收起完整帮助)→ `─` 全宽分隔线 → `[Skills]` `[Extensions]` 分节列表(节标题黄色、内容 dim,同样可展开)。
2. **消息区(提交进终端 scrollback,Inline 视口,保留原生回滚)**:
   - 用户消息:背景色块(pi 的 userMessageBg 方案);
   - assistant:真 Markdown 渲染(标题/列表/行内代码/链接着色),代码块用 syntect 语法高亮 + 边框;
   - thinking:dim 灰;工具调用:`⏺ name` 语义色 + 按状态着色(成功绿/失败红),输出默认折叠为前几行 + `… (N more lines, ctrl+o)`;
   - 错误红 / 警告黄 / 成功绿,语义化 token 收拢在 Theme 结构里(默认 dark 主题,对齐 pi 的 dark.json 语义)。
3. **底部固定区**:多行编辑器(shift+enter / ctrl+j 换行,enter 发送,保留 undo/kill-ring/历史),边框为动态状态条(`── thinking ──` 形式,颜色随状态:working=spinner 色、`!` bash 模式=绿、idle=dim);spinner 动画帧;两行 footer:左 `~/cwd (git分支) • session名` + `↑↓ tokens $cost · ctx%`(>70% 黄、>90% 红),右侧右对齐 `model · thinking level`。
4. **交互**:esc 中断、ctrl+c 清空/再按退出、`/` 命令(保留现有 slash)、`!` bash 透传(tokio::process 执行,输出注入对话上下文,执行期间编辑器边框变绿)、ctrl+o 全局展开/收起(工具输出 + 启动帮助/资源列表联动)。

## 结构改动
**crates/latent-tui 重写**(保持 docs/10 约束:不依赖任何内部 crate):
- 新依赖:`ratatui`、`crossterm`(event/terminal/raw mode/按键解析全部替换手写实现)、`syntect`;
- 删除 `screen.rs`/`diff.rs`/`ansi.rs`/`keys.rs`/`terminal.rs`,新建:
  - `app.rs` — `Viewport::Inline` 渲染核心 + `insert_before` 提交消息到 scrollback(crossterm 事件循环;注意 docs/08 踩坑记录中的光标锚定/折行经验仍适用于 Inline 视口 resize);
  - `theme.rs` — 语义色 token(user/assistant/thinking/tool_*/error/warning/md_*/footer/border_*);
  - `components/` — `markdown.rs`(含 syntect 高亮、ANSI 感知 wrap,复用 `width.rs` 的 CJK 宽度)、`editor.rs`(多行化,迁移现有编辑逻辑)、`loader.rs`(spinner)、`tool_card.rs`(含折叠/展开)、`select_list.rs`(保留)、`header.rs`/`footer.rs`;
- 更新 `docs/08`:"TUI 零依赖"决策改为"ratatui 为底的自有组件层"。

**crates/latent-cli 的 interactive.rs 拆分**为 `modes/interactive/` 目录:`mod.rs`(事件循环 tokio::select)、`ui.rs`(TuiUi 状态机 + ExtensionUi 实现)、`view.rs`(视图组装)、`keys.rs`(按键分派)、`usage.rs`(用量/ctx%)、`bash.rs`(`!` 透传)、`replay.rs`(会话回放按新渲染重画);现有 `slash.rs` 保留。print/json/rpc 模式不动。

## 实施顺序
1. latent-tui 核心切换:Inline app + theme + 事件循环,迁移 Text/SelectList,编译通过;
2. 组件:markdown+syntect → 多行 editor → loader → tool_card → header/footer;
3. cli 侧拆分 interactive.rs 并接入新组件(横幅/分隔线/资源列表/状态栏/配色);
4. `!` bash 透传、ctrl+o 展开状态、spinner tick;
5. 回放与测试:迁移现有 ~470 行 interactive 测试,新增组件单测(markdown wrap、footer 格式化、多行 editor);`cargo test` 全绿。

## 风险
- syntect 会明显增大编译时间与二进制体积(已确认接受);
- Inline 视口在终端 resize 时的重排需按踩坑记录自管折行,不信任外部宽度;
- 现有基于 stty 的测试若依赖 raw-mode 细节,需随 crossterm 调整。
