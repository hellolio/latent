# Web Access 上限体系统一 + workflow 改用户配置 + 提示词修复

## 设计原则

1. **agent 兜底不动**：`DEFAULT_TOOL_RESULT_MAX_CHARS = 20_000` 保持不变。
2. **所有工具自我上限 = agent 上限 − 2k（18k）**，同一配置源派生；2k 余量保证"内容 + 指引"永不触发 agent 头尾裁剪。
3. **web 内部按比例分配**：多 URL / 多 query 各分 `总预算 / 条数`，每条都有内容幸存。
4. **workflow 不暴露给模型**：从 web_search 的 schema 和参数解析中删除，改为 web-search.json 用户配置；模型只从输出中得知"这是生成的摘要"。

## 第一步：agent 层暴露统一派生值

- `crates/latent-agent/src/loop_.rs`：
  - 新增 `pub const TOOL_RESULT_MARGIN_CHARS: usize = 2_000;`
  - 新增 `pub fn tool_self_output_limit(tool_result_max_chars: usize) -> usize`：`tool_result_max_chars.saturating_sub(TOOL_RESULT_MARGIN_CHARS)`，下限保护 4_000；入参为 0（= 未限制）时返回 0，工具回退自身默认值。

## 第二步：装配层注入同一来源

- `crates/latent-cli/src/assembly.rs`：把 `AgentLoopConfig.tool_result_max_chars` 的同一来源值传给：
  - `WebContext` 新字段 `tool_result_max_chars: usize`（latent-web/src/tools/mod.rs:34-44）；
  - bash / read 工具的新构造参数（见第四步）。

## 第三步：workflow 改为用户配置（不暴露给模型）

1. **配置项**（`latent-web/src/config.rs`）：`WebSearchConfig` 新增 `workflow: String`（默认 `"none"`，合法值 `none` / `auto-summary`，解析时校验），沿用现有 `~/.latent/web-search.json` + 项目级覆盖机制；配置示例注释补上 `"workflow": "auto-summary"`。摘要模型沿用已有的 `summaryModel`（已实现"未配置 → 回退主模型"，llm.rs:23-28）。
2. **schema 移除**（`latent-web/src/tools/web_search.rs:57-88`）：删除 `workflow` property。
3. **参数解析移除**（`latent-web/src/tools/mod.rs:176-196`）：删除 workflow 解析分支（模型若仍传该键则被忽略）；`SearchParams` 的 `workflow_none` 改由 `context.config.workflow` 决定。
4. **输出告知模型**：`workflow = auto-summary` 生效时，摘要输出头部加一行标注，例如：
   `This is an auto-generated summary of the search results (configured in web-search.json). Full search results are stored as responseId "{search_id}" — retrieve via get_search_content.`
   ——同时落实"auto-summary 补 searchId"的 P1 修复；`workflow = none`（默认）时行为不变，直接返回原始结果。
5. **描述清理**：`web_search_description()`（prompts.rs:49）删除 summary-review 和 auto-summary 两处分句（摘要已是配置行为，描述不再提）；删除常量 `WEB_SEARCH_PARAM_WORKFLOW`（:76）。

## 第四步：bash/read 对齐同一上限

- `crates/latent-tools/src/truncate.rs`：在现有行/字节截断后增加字符预算上限（bash 保留尾部语义、read 保留头部语义，附省略标注）。
- `create_bash_tool` / `create_read_tool` 增加可注入的输出上限参数（带默认值的 config 结构，不破坏现有调用点；lib.rs:83-113 与 assembly 装配处接线）。
- 行为说明：bash 内联输出从最多 50KB 收敛到 ~18k 字符（已有 fullOutputPath 落盘兜底）；read 续读提示机制不变。

## 第五步：web 侧其余修复

1. **上限计算**（`WebContext::max_inline_chars()`）：`min(配置值, tool_self_output_limit(agent值))`，为 0 时用配置值。所有分页指引/默认 limit 取值点自动对齐。
2. **fetch_content 按比例**（fetch_content.rs:214-263）：按**抓取成功数**均分预算，失败条目不占额；每条切片附 `responseId + urlIndex + offset` 续读指引；最终过 `bound_search_presentation` 护栏。
3. **web_search 按 query 均分**（web_search.rs:236-334）：每条 query 输出截到 `max_inline / query_count`，被截的附 searchId 取回提示；最终过护栏。
4. **for_truncation 差异化**（web_search.rs:272-302）：截断版指引额外引导使用/启用 `get_search_content`。
5. **Research artifact 紧凑 JSON**（get_search_content.rs:228-229）：`to_string_pretty` → `to_string`。
6. **单 query 免选**（get_search_content.rs:335-349）：Search 分支仅一条 query 且未传参时默认取 index 0，不再报错。
7. **web_access notifier 缺失文案**（web_access.rs:67-84）：无 notifier 时改为"工具将在下次请求生效，请继续处理用户请求"。

## 第七步：测试与验证

- 新增单测：`tool_self_output_limit`；fetch_content / web_search 均分（失败条目不占额、单条不缩水）；截断/未截断指引差异；单 query 免选；web_access 无 notifier；workflow 配置解析与非法值拒绝；auto-summary 输出含摘要标注 + searchId。
