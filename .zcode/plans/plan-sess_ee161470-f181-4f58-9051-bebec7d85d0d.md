# latent 测试标准 + "像人一样" E2E 测试建设（v2：本地 mock LLM 服务方案）

## 方案要点（相对 v1 的变化）

- **放弃 `--script` 选项**（不改主程序代码）。E2E 的确定性由**本地 mock LLM 服务**提供：一个用 Python 起的 SSE 服务器，伪装成 LLM 端点返回预设响应。
- 真实二进制通过现有的 `models.json` provider override（`baseUrl` 覆盖到 `http://127.0.0.1:<port>`）连上它——该机制已存在（`latent-core/src/model.rs:100`），无需改动。
- 响应格式参考项目现有测试 `crates/latent-ai/tests/adapters.rs` 的本地 SSE 服务器（anthropic-messages 格式）。
- 其余不变：pexpect 驱动真实二进制、交付"标准文档 + 基建 + 5 个示例场景"、不建 CI。

## 交付物

### 1. 测试标准文档 `docs/11-testing.md`

四层测试金字塔，每层明确测什么、放哪、命名约定、何时必须写：

| 层 | 范围 | 位置 | 驱动方式 |
|---|---|---|---|
| L0 单元 | 纯函数/单一类型 | 各 crate `#[cfg(test)]` | `cargo test`（已有） |
| L1 集成 | crate 间协作、trait 接缝 | `crates/*/tests/` | `cargo test`（已有） |
| L2 TUI 屏幕 | `TuiApp` 视口渲染成屏的最终效果 | `crates/latent-tui/src/app.rs` | ratatui `TestBackend`（新增） |
| L3 真终端 E2E | 完整二进制 + 真实 PTY + 本地 mock LLM，按用户使用流程 | `tests/e2e/` | Python pexpect（新增，核心） |

附"改动类型 → 必须补的测试层"映射表（如改 key.rs → L0；改交互 handlers → L2/L3；新增斜杠命令或改交互流程 → L3 场景）。

### 2. L3 基建 `tests/e2e/`（核心）

- **`mock_llm.py`**：本地 mock LLM 服务（Python 标准库 asyncio/HTTP，无重依赖）——
  - 按 anthropic-messages SSE 格式返回预设事件流（格式抄 `tests/adapters.rs` 的服务器）；openai 格式留扩展点；
  - 由场景 JSON 驱动：按请求顺序逐 turn 返回 `text` / `tool_calls` / `error`，支持 `delay_ms`（做 abort 测试）；
  - **记录收到的每个请求**（JSONL），供测试反向断言（如：工具结果是否真的随第二轮请求发出）；
  - 随机空闲端口启动，测试结束自动关闭。
- **`harness.py`**：`LatentApp` 类封装——
  - 在临时目录造隔离 `HOME`（避免污染真实 `~/.latent`），写入指向 mock 服务的 `.latent/models.json`（provider override + dummy api_key）；
  - `pexpect.spawn` 启动 `LATENT_BIN`（env 指定二进制路径，默认 `target/debug/latent`），显式 `--mode interactive --provider <mock-provider>`；
  - `send(text)` 模拟打键、`expect_text(pattern, timeout)` 断言屏幕出现内容、`screen()` 用 pyte 把 ANSI 输出解析回"用户看到的屏幕文本"、`mock.requests` 读 mock 服务记录的请求、`quit()` 优雅退出并校验退出码。
- **`requirements.txt`**：`pexpect`、`pyte`。
- **`README.md`**：运行方式（先 `cargo build` 再 `pytest`）、场景与断言编写规范（对应标准文档 L3 节）。

### 3. L3 示例场景（5 个，每个 = `test_*.py` + `scenarios/*.json`）

1. `test_startup.py` —— 启动 interactive，看到横幅、footer（模型名/cwd）、编辑器框；
2. `test_ask_and_reply.py` —— 输入问题回车 → mock 返回固定回复流式上屏 → 回到可输入状态；并反向断言 mock 收到的请求里带了系统提示词/用户消息；
3. `test_tool_roundtrip.py` —— mock 第一轮返回 tool_calls → latent 执行内置工具 → 第二轮请求里带上工具结果（mock 侧断言）→ 最终回复上屏；
4. `test_abort.py` —— mock turn 带 `delay_ms` 使回复进行中 → 按 Esc → 屏幕出现中断状态；
5. `test_quit.py` —— Ctrl+D（或 Ctrl+C 双击）退出 → 进程干净结束。

### 4. L2：TuiApp 接入 ratatui `TestBackend`（小改动）

`crates/latent-tui/src/app.rs`：backend 可注入（`TuiApp::open` 保持不变，加测试构造路径，取侵入最小方案），替换 placeholder 测试为 2-3 个屏幕级断言（viewport 内容、编辑器框 + footer 组合）。

### 5. 不做（标准文档中列为后续项）

CI、insta snapshot、Windows 原生 PTY（pexpect 不支持，文档注明走 WSL）。

## 实施顺序

1. `mock_llm.py` + 最小连通验证（手工起服务 + `models.json` override，确认真实二进制能跑通一轮对话）；
2. `harness.py` + 前两个示例场景；
3. 其余三个场景；
4. TuiApp TestBackend 接入；
5. 标准文档 `docs/11-testing.md`（最后写，与实际基建一致）。

## 风险与验证

- 风险：anthropic 适配器可能对 api_key/请求头有前置要求——实施第 1 步时最先验证，dummy key 走 config 的 `api_key` 字段解决；
- 验证：`cargo test --workspace` 全绿；`cd tests/e2e && pytest -v` 5 个场景全绿（macOS 本机实跑）；故意改坏一个断言做一次红→绿验证，确认 E2E 真能捕捉问题。
