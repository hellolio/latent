# 子 agent 会话完整落盘(与主会话同格式,文件名带 tag)

## 需求
子 agent(task 工具子运行 与 /subagent 平行会话)的 session 与主 agent 一样保存到文件:同一套 rpi-session JSONL 格式与使用方法(消息/usage/contextSnapshot 及 ContextRef entry 全部一致),文件名加 tag 区分。

## 改动

### 1. rpi-session
- `create_session_in_dir` 增加 `tag: Option<&str>` 参数:文件名 `<项目前缀>__<tag>__<session-id>.jsonl`(tag = run id 或 agent 名,做文件名安全净化);无 tag = 现状。
- `find_latest_session_file` **排除带 tag 的文件**(`--continue` 永远只续主会话)。
- `append_context_snapshot` 不变——子会话有自己的 manager,快照自然落自己的 `.ctx/` 目录并在自己 JSONL 里记 ContextRef,与主会话机制完全一致。

### 2. rpi-core
- 新类型 `ChildStore { sink: Arc<dyn SessionSink>, stream_options: StreamOptions }` + `ChildStoreFactory = Arc<dyn Fn(&str) -> Result<ChildStore, String> + Send + Sync>`(subagent 模块定义,装配层注入实现)。
- `session.rs` 导出 `create_session_persistence_subscriber(sink)`——复用现有私有 `SessionBridge` 的持久化半边(MessageEnd → sink.append + usage entry),供裸子 agent 挂载。
- `ChildSpec` 增加 `persistence: Option<ChildStore>`:`run_child` 据此挂持久化订阅者 + 设 `stream_options`;`SubagentDeps.child_store_factory` 注入 task 工具(同步/异步子运行 tag = run id);`SubagentSessionFactory.child_store_factory` 注入 `/subagent` 会话(tag = agent 名,`create()` 时经 factory 现场建文件,config 的 `session_sink`/`stream_options` 接上)。

### 3. assembly
- `build_session` 内构建 `child_store_factory` 闭包:跟随主会话存储策略(`SessionStore::Memory` → None 不落盘;`New/Resume` → 同目录 `create_session_in_dir(tag)`,sink 复用现有 `SessionManagerSink` 机制,on_payload → 该 manager 的 `append_context_snapshot`);注入 SubagentDeps 与 factory。

## 行为
- `~/.rpi/sessions/` 下:主会话 `Users-kin-...__<id>.jsonl`;子会话 `Users-kin-...__<tag>__<id>.jsonl`(`.ctx/` 快照目录同理带 tag);
- 子会话 JSONL 内容与主会话条目格式完全一致(Message/Usage/ContextRef/ModeChange 等 entry);
- 纯内存模式(SessionStore::Memory,如测试)不落盘,行为不变。

## 测试
- L0:create_session_in_dir 带 tag 的文件名与 find_latest 排除;
- L1:task 子运行 + /subagent factory 各一条——断言会话文件生成、消息/usage/快照 entry 落盘、`--continue` 不选中子文件;
- 全量 `cargo test --workspace` + clippy。
