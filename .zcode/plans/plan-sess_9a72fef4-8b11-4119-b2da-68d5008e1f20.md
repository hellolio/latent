# rpi 模式节改造：从"每请求尾插"改为 Claude Code 式 append-only 持久节点

## 目标语义

- 模式切换（含会话初始模式）时，向会话转录**追加一条持久的 `ModeSection` 消息**，落盘、进上下文，位置永久固定在追加点——历史前缀从此逐字节稳定，每回合缓存命中最大化。
- 旧节点自然留在历史（"entering" / "exiting" 文本已成对自描述，语义连贯）。
- 去重规则：仅当新模式的节文本 ≠ 转录中最后一条 `ModeSection` 内容时才追加（老会话 resume、`--session-mode` 覆盖、重复切换都由此收敛）。
- 删除 `ModeHooks` 的每请求尾插；压缩/溢出恢复后若当前模式节点已不在我上下文中，补追加一条。
- 决策（已确认）：仅切换时追加，不做每回合重复注入。

## 实现步骤

### 1. rpi-agent：新增 `ModeSection` 消息变体
- `crates/rpi-agent/src/message.rs`：新增 `AgentMessage::ModeSection { content: String }`，serde role tag `modeSection`（snake_case 判别符，遵循 BashExecution 先例）；补 serde 往返单测（:134-165 处）。
- `crates/rpi-agent/src/hooks.rs` PassthroughHooks（:165-226）：新增折叠规则 `ModeSection → Message::developer(content)`（原位保留，不折叠成 user XML——openai-completions 映射 developer 角色，anthropic 已有任意位置 developer→user 降级合并逻辑，两条适配器路径都现成）。
- 注意 `rpi-session` 若对 AgentMessage 有穷尽 match（entry.rs / projection.rs），补对应分支（`Message` entry 透传路径应自动携带新变体）。

### 2. rpi-core：apply_mode 追加节点 + 删除 ModeHooks
- `crates/rpi-core/src/session.rs` `apply_mode`（:529-552）：保留 mode_change entry 写入；新增——查转录末尾的 `ModeSection`，内容不同则 push `AgentMessage::ModeSection` 进转录并 `sink.append` 落盘（仿 `record_bash_execution` :475-496 写法）；`apply_mode_without_persist` 走同一逻辑（恢复时历史里已有节点则去重跳过；老会话文件无节点则补一条，天然向后兼容）。
- 新增 `ensure_mode_node()`：转录中不存在与当前 `mode_section()` 文本一致的节点时补追加。在 `compact()`（:645-658）、overflow 恢复（`run_with_recovery` :675-746 的 trim 分支后）调用。
- `crates/rpi-core/src/permission/hooks.rs`：删除 `ModeHooks` 整个 struct（:76-98）及其 `mode_text` cell。
- `crates/rpi-core/src/subagent/factory.rs`（:82-95, :126-141）：子会话装配去掉 Mode 层，初始模式节由 `apply_mode_without_persist` 的追加逻辑产生。

### 3. rpi-cli：装配与恢复链路
- `crates/rpi-cli/src/assembly.rs`：:750-779 hooks 洋葱改为 `ApprovalHooks → (ExtensionHooks) → PassthroughHooks`（Mode 层移除，`mode_section_cell` 相关 plumbing 清理）；:1064-1073 新会话/resume 的 `set_mode`/`apply_mode_without_persist` 不变（节点追加在 apply_mode 内部完成）；:325 `/new` 同理。
- `crates/rpi-ai/src/types.rs` :205-209 Developer 消息注释更新（不再是"每请求追加、不进转录"）。

### 4. rpi-session：压缩交互
- `crates/rpi-session/src/compaction.rs`：`serialize_conversation`（:471-555）加 `ModeSection` 分支（短文本纳入摘要输入）；切点判定 `is_cut_point_message`（:245-255）允许在 ModeSection 处切（非 toolResult）。当前模式约束的存活由步骤 2 的 `ensure_mode_node` 兜底（压缩后补追加）。

### 5. 测试同步更新（探索确认的锚点）

## 已知取舍（不处理，仅记录）
