# 总体实现方针 + Workspace 骨架

## 一、交付物 1：方针文档 `docs/10-implementation-policy.md`

在 00-09 文档之上提炼并**固化**实施方针（09 文档已有 crate 划分和 trait 草图，本文档不重复设计细节，而是定“开发规则”），内容包括：

1. **架构总纲**：7 crate 布局与四层单向依赖（modes→core→agent→ai，引用 09 B1），crate 级可拆卸——`rpi-session`/`rpi-tools`/`rpi-tui` 为可选组件，`rpi-core`/`rpi-cli` 通过 trait 注入选择性装配，移除任一可选 crate 其余仍可编译。
2. **模块契约（独立性规则）**：每个 crate 对外只暴露三类东西——**工厂函数**（`create_*()`）、**trait 接口**、**纯类型**；调用方只依赖 trait 不依赖具体实现类型；跨 crate 依赖严格按依赖图，禁止反向依赖与同层互依。
3. **六个接缝清单**（引用 09 A2/B2 的结论）：`Provider` trait（循环↔AI 层）、`LoopHooks` trait（宿主↔循环）、`Tool` trait（循环↔工具）、`ExtensionUi`/`ExtensionActions`（core↔扩展/mode）、`Subscriber`（事件汇）。这是“可拆卸”的技术保证：换实现不动接缝。
4. **框架先行开发规则**：
   - Phase 0（本次）：workspace 骨架，全 crate 编译通过，trait 定型，stub 实现 + Mock provider 验证接缝；
   - Phase 1-N：按 09 B6 的 M1-M6 里程碑逐模块纵向填充（M1 rpi-ai 单适配器 → M2 循环 → M3 session → M4 core → M5 tui/扩展 → M6 rpc）；
   - 每个模块的验收标准：独立 `cargo test` 通过 + 不破坏其余 crate 编译。
5. **差异点默认决策**（直接采纳 09 B5 的建议，避免后续反复）：失败 assistant 消息保留进上下文、partial 消息改为 buffer + 定稿 push、details 用 `serde_json::Value`、扩展起步用编译期注册、串行订阅保序语义。

## 二、交付物 2：Cargo workspace 骨架（可编译、接缝可验证）

在 `/Users/kin/Documents/10source/rpi/` 根下建 workspace，`docs/` 保留不动：

```
rpi/
├── Cargo.toml              # [workspace] members = crates/*，统一依赖版本（workspace.dependencies）
├── docs/                   # 现有文档不动，新增 10-implementation-policy.md
└── crates/
    ├── rpi-ai/             # 零内部依赖。Provider trait、Model、AssistantMessageEvent 流类型、
    │                       #   TranscriptContext、StreamOptions；工厂 create_provider()（stub）+ MockProvider
    ├── rpi-agent/          # 依赖 rpi-ai。AgentMessage 枚举（含 Custom 逃生口）、AgentEvent、
    │                       #   Tool trait、LoopHooks trait（默认空实现）、Agent 结构 + create_agent()、
    │                       #   run_agent_loop() 骨架（状态机 Phase enum 占位，M2 填充）
    ├── rpi-session/        # 只依赖 rpi-agent 的类型。Entry 枚举占位、SessionManager + create_session()（stub）
    ├── rpi-tools/          # 只依赖 rpi-agent 的 Tool trait。工具注册表 + create_default_tools()（空注册）
    ├── rpi-core/           # 依赖以上全部。AgentSession、ExtensionApi/ExtensionUi/ExtensionActions trait、
    │                       #   create_agent_session() 装配工厂（演示“trait 注入组装”）
    ├── rpi-tui/            # 占位 crate（零依赖，M5 填充）
    └── rpi-cli/            # bin。main 解析参数；`--mock` 模式用 MockProvider 走通
                            #   cli→core→agent→ai 全链路，验证接缝成立（不联网）
```

关键实现点：

- **骨架可运行验证**：`cargo run -p rpi-cli -- --mock` 用 MockProvider（ canned 流式事件）走完 create_agent_session → Agent.prompt → 事件打印，证明所有 trait 接缝真实可用，而不是只有空壳。
- **核心 trait 按 09 B3 草图定型**：`LoopHooks`（convert_to_llm 必填 + 其余默认实现）、`Provider`（失败编码进流）、`Tool`（name/schema/execute/update sink）。
- 基础依赖统一在 workspace 层声明：tokio、async-trait、serde、serde_json、tokio-util（CancellationToken）、thiserror、futures。
- 每个 crate 带最小测试（trait 默认实现、mock 流、装配函数），保证 `cargo test --workspace` 通过。
