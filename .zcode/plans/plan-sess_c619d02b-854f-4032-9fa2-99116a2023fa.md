# 交付物：根目录开发计划文档（本次只写文档，不写实现代码）

在仓库根目录创建 **`GATEWAY_PLAN.md`**——一份自包含的开发指南，其他 agent 无需本对话上下文即可按文档开发。文档全文约 500+ 行，中文，结构如下：

## 文档章节

**§0 背景与上游阅读指南**：latent 是什么、OpenClaw（MIT，github.com/openclaw/openclaw）是什么、二者关系（OpenClaw 的 agent 底层即 latent 的上游 pi）；**总原则：行为语义、常量、协议、边界情况一律先查 OpenClaw 对应源文件再动手**；上游路径可能漂移（文档写作时基于 2026.10 的 main），路径失效时按文中给的关键词搜索定位。

**§1 三 crate 划分与依赖方向**：latent-channel（L1 零内部依赖）/ latent-runtime（L2 装配层）/ latent-gateway（L3 引擎+bin）；依赖图、编译隔离验收命令（cargo tree 三条断言）。

**§2 latent-channel 规格**：完整文件树；`types.rs` 每个类型的字段级定义（Segment/InboundMessage/OutboundMessage/ChatRef/ChannelEvent…）；`plugin.rs` trait 完整 Rust 签名；宿主层机制精确参数（typing keepalive 3s/TTL 60s/连续失败 2 停、防抖默认 0ms/×5 窗口/2048 键、chunk 4000/length|newline/括号感知断点/code fence 闭合重开）；feature 门控 Cargo.toml 原文示例；三渠道实现要点。

**§3 latent-runtime 规格**：从 latent-cli 迁移的文件与函数清单（assembly.rs 全量、resolve_provider_and_model、resolve_session_store、print_session_list、session_event_to_json、PrintSubscriber、slash 解析层、landlock helper 分发）；`rpc_approval` 字段删除方案（2 处引用的具体位置与改法）；latent-cli re-export 兼容层。

**§4 latent-gateway 规格**：目录树；`gateway.json` 完整配置示例（逐字段注释）；session key 公式与 dmScope 四档；`auto_reply/` 各文件职责与队列语义（steer|followup|collect|interrupt、cap 20、drop、500ms 批防抖、与 latent session.steer/follow_up/abort 的映射）；envelope 格式；reply_dispatcher 保序规则（sendChain、final 只发一次、NO_REPLY 跳过）；commands 表（普通命令 vs owner 特权命令分列）；approval/pairing/state；控制面协议三种帧的 JSON 示例、connect 握手时序、方法表与事件表。

**§5 安全设计（硬性要求）**：full-access 仅 owner 可切、审批仅 owner 可应答（本对话已拍板）；QQ 反向 WS 默认 127.0.0.1 + accessToken 必填 + Header 校验；控制面 token 未配置拒绝启动；凭据 $ENV/!shell 三来源；panic 边界；日志 redact；已知限制清单（提示注入防线、无限速、单工作区、MCP 子进程倍增）。

**§6 实现细节对照表（核心章节）**：每个模块一行——"实现前必读的 OpenClaw 源文件路径 + 已核实的关键语义"。覆盖：queue（auto-reply/reply/queue.ts + docs/concepts/queue.md）、防抖（auto-reply/inbound-debounce.ts）、分段（auto-reply/chunk.ts）、envelope（auto-reply/envelope.ts）、session key（routing/session-key.ts）、typing（channels/typing.ts）、@判定（channels/mention-gating.ts）、群策略（docs/channels/groups.md）、配对（docs/channels/pairing.md）、channel 接口（channels/plugins/types.plugin.ts + extensions/telegram/ 为参照实现）、协议（packages/gateway-protocol/src/schema.ts + docs/gateway/protocol/*）、命令（auto-reply/reply/commands-*.ts）、健康监控（gateway/channel-health-monitor.ts）、配置（config/types.openclaw.ts + docs/gateway/configuration.md）。另列"已知坑"清单：message-id 去重先于 ACK、防抖窗口首条固定不可顺延、OneBot echo→oneshot 关联与心跳、Telegram getUpdates offset/409 冲突、token 走 Header 不走 query、退出码 78、feature unification 语义等。

**§7 实施阶段与验收**：阶段 1-5 各自的产出、硬门槛（三件套全绿零警告）、cargo tree 断言、集成测试清单（含安全用例：非 owner 切 full-access 被拒、非 owner /approve 无效、审批超时 Deny、无 token 拒绝启动、陌生人 pairing、非白名单群丢弃）。

**§8 与 OpenClaw 的偏离记录**（9 条，含会话存 JSONL、单 agent MVP、steer 时序、重启不恢复在途 run、安全模型更严等）。

**§9 仓库工程规范**：unsafe forbid、依赖 pin 到根 Cargo.toml、clippy 零警告、camelCase/毫秒时间戳、根 Cargo.toml 需新增的条目原文（default-members、tokio net、tokio-tungstenite/axum pin）；以及本对话已定的选型结论（QQ=NapCat/OneBot 11 反向 WS、微信=企微智能机器人 WS 长连接、Telegram 长轮询、群=每群一会话）。
