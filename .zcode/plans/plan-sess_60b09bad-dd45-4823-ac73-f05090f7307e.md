### P2（修有明确语义的；其余记录在报告标注不改及理由）
- `trim_oldest_messages` 会删掉打头 system baseline（`agent.rs:256-267`）
- `follow_up_mode` 死配置：loop 分派 follow-up 时按各自 mode（`loop_.rs:487-501`）
- `max_tokens=0` 消毒（两个 adapter）
- 流中错误保留已流出的部分内容（错误消息附已累积文本，两个 adapter）
- edit 混合行尾：只改写被编辑行，不动未编辑区域（`edit.rs:230-234`）
- truncate 恰好等于 max_bytes 误报截断（`truncate.rs:65`）
- read `limit:0` 参数校验报错；加二进制文件检测（NUL 字节，同 grep）
- Ctrl+C 双击窗口被 Enter/Ctrl+O 重置（`handlers.rs:87-139`）
- `/compact` 带参数：明确警告参数未生效（已有提示，确认为阻断式警告）
- `session_name()` 跳过 None 导致旧名复活（`manager.rs:267-279`）
- `set_model`/`set_thinking_level` 落盘与消息 append 乱序：改为内联同步 append（`rpi-core/session.rs:518-537`）
- apiKey env 变量存在但为空 → 视为未命中（`config.rs:158-165`）
- 性能：`LineDecoder` 改扫描偏移避免前缀搬移（`sse.rs:70-81`）；流式预览折行增量/节流（`view.rs:194-199`）

**记录不改**（报告说明理由）：fail-open confirm（docs 已声明为决策）、PID 复用理论窗口、跨进程文件锁、grep 同步 IO、replay 全量高亮、InjectionDepth 计数竞态、未知 StopReason 映射策略。

每项修复补对应 Rust 单元测试；修完全量 `cargo test` 回归。

## 阶段 C：新增 e2e 测试（tests/e2e/，按 README 方法）
每条 = `scenarios/*.json` + `test_*.py`，mock 需扩展的场景先扩 `mock_llm.py`：

- **T15 并行多工具**：一轮 2 个 tool_calls → 卡片按序上屏、第二轮请求体结果齐全且有序
